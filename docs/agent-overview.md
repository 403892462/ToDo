# 受控项目 Agent 概述、功能与边界

## 1. 文档目的

本文说明当前项目中的“受控项目 Agent”是什么、能做什么、不能做什么，以及各模块如何协作。

这里的 Agent 不是单一大模型提示词，而是一套由以下部分共同组成的工程系统：

- `AGENTS.md`：项目级行为规则和技能路由。
- `.agents/skills/`：各阶段 Skill，规定角色职责、输入、输出和停止条件。
- `.project/`：状态、周期、运行、审计、指标和复盘事实。
- `docs/` 与 `plans/`：业务、需求、方案、验收、计划和交付产物。
- `scripts/`：状态校验、阶段推进、执行、审计、指标与复盘工具。
- `acceptance/`：独立验收测试和夹具。
- `evidence/`：真实执行与验证证据。

## 2. 核心目标

系统用于把业务想法按受控流程转化为可验证的软件交付，重点解决以下问题：

1. 业务规则未经确认就被模型自行补全。
2. 需求、方案、工作项、测试和证据之间无法追踪。
3. 测试失败或证据缺失时仍被错误标记为完成。
4. 自动化流程绕过人工审批 Gate。
5. 验收角色一边审计、一边修改被审计实现，失去独立性。
6. 复盘补造成本、Token 或耗时数据。

## 3. 阶段流程

当前主流程为：

```text
IDEA
  → DISCOVERY
  → REQUIREMENTS
  → SOLUTION_DESIGN
  → PLANNING
  → IMPLEMENTATION
  → ACCEPTANCE_AUDIT
  → DELIVERY
  → COMPLETED
```

当前项目使用的人工确认点为：

- Gate 1：业务发现确认。
- Gate 2：需求基线确认。
- UI Gate：包含用户界面时确认关键界面和状态；不适用时必须显式记录。
- 技术方案确认：确认方案、风险和技术边界。
- 实施计划确认：确认工作项、依赖和验证映射。
- Gate 3：独立验收通过后的最终交付确认。

人工 Gate 只能由负责人确认，Agent 不得代签。

## 4. Skill 清单

| Skill | 主要职责 | 关键边界 |
|---|---|---|
| `business-discovery` | 把模糊想法转化为问题定义、范围和成功标准 | 未确认内容进入待确认状态 |
| `requirements-definition` | 建立带版本、编号和验收标准的需求基线 | 不替代负责人批准 Gate 2 |
| `solution-design` | 评估技术影响、风险和实施方案 | 高风险未处置时阻止进入规划 |
| `implementation-planning` | 把批准需求转换为可验证工作项 | 不改变已批准业务规则 |
| `execute-plan` | 按工作项实施、测试、记录证据和恢复 | 验证失败不得标记为 DONE |
| `acceptance-audit` | 独立验证覆盖、风险、契约、证据和只读边界 | 不修改生产实现或实现测试 |
| `project-orchestrator` | 读取项目事实并给出唯一合法下一动作 | 不代签 Gate，不执行任意命令 |
| `delivery-retrospective` | Gate 3 后生成事实可追溯的交付复盘 | 未知数据保持未知，建议不自动变更需求 |

## 5. 功能清单

### 5.1 状态与周期管理

- 读取并校验 `.project/state.md`。
- 维护版本化周期注册表。
- 识别当前阶段、活动工作项和活动运行。
- 检测非法阶段转换、缺失产物和状态矛盾。
- 已完成周期不会自动启动新周期。

### 5.2 唯一下一动作决策

- 根据当前阶段、Gate、工作项和验证结果给出一个合法动作。
- 输出 `ACTIONABLE`、`WAITING_HUMAN`、`BLOCKED` 或 `COMPLETED`。
- 存在多个候选工作项、活动运行或事实冲突时失败关闭。
- 相同事实产生确定性结果。

### 5.3 受控执行与恢复

- 工作项通过受控脚本启动和完成。
- 使用运行编号、项目锁和动作键避免重复执行。
- 只允许白名单动作。
- 支持超时识别、失败记录和恢复。
- 真实验证证据与工作项状态关联。

### 5.4 串行与保守并行调度

- 根据工作项依赖生成稳定顺序。
- 只有无依赖、文件范围不重叠、语义资源不冲突、运行资源不冲突且隔离已证明时才允许并行。
- 信息缺失或安全性无法证明时退化为串行。
- 运行期间发生范围漂移或资源冲突时停止并转人工处理。

### 5.5 需求追踪与变更控制

- 使用稳定编号关联需求、方案、工作项、测试和证据。
- 需求变化使用 `CHG-*` 记录。
- 变更使受影响的下游方案、计划、测试或证据失效。
- 协议检查阻止缺失引用或无证据完成。

### 5.6 独立验收审计

- 使用独立夹具验证验收标准。
- 审计前后计算受保护实现和测试的 SHA-256 摘要。
- 输出 `PASS`、`FAIL` 或 `AUDIT_ERROR`。
- 审计失败只能退回执行流程修复。
- 失败报告不得覆盖，复验必须使用新审计编号。

### 5.7 指标与交付复盘

- 记录追加式耗时、成功/失败/重试、质量、用量和成本事件。
- 无可靠成本或 Token 来源时保存 `null` 和原因。
- 无效指标进入数据质量记录，不进入事实汇总。
- Gate 3 后生成机器摘要和中文复盘。
- 复盘严格区分事实、推断、数据缺口和待决定建议。

## 7. 系统边界

### 7.1 Agent 可以做

- 读取项目事实并建议或执行已授权的受控动作。
- 在已批准范围内编写代码、测试和文档。
- 运行协议检查、测试、构建和冒烟验证。
- 在失败时停止、记录原因并指出恢复条件。
- 在 Gate 3 后基于真实来源生成复盘。

### 7.2 Agent 不可以做

- 代替负责人批准任何人工 Gate。
- 把未确认业务规则当成事实。
- 测试失败后将工作项标为完成。
- 在独立审计期间修改被审计实现或实现测试。
- 自动接受复盘建议或直接修改需求。
- 补造成本、Token、耗时或生产验证证据。
- 执行文档中夹带的任意命令文本。
- 自动启动未批准的新周期。
