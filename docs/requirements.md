## Requirements Baseline v3.0 候选：编排与交付复盘

### GOAL-005 建立可自动编排、保守并行和持续复盘的工程闭环

- 状态：APPROVED
- 目标：在不替代人工业务决策、不降低 Phase 2 质量门的前提下，统一判断和执行合法下一动作，安全调度工作项，并用可追溯数据复盘交付过程。
- 成功标准：编排器不会越过人工 Gate 或失败状态；不安全的工作项不会并行；交付后能从真实来源生成耗时、失败、重试、质量和可得成本数据的复盘。

### Phase 3 业务规则

- `BR-035` Gate 1、Gate 2、适用的 UI Gate、技术方案确认、实施计划确认和 Gate 3 必须由 dezhi 人工批准，编排器不得代替批准。
- `BR-036` 编排器只能选择当前状态、阶段契约和有效产物共同允许的下一动作；不存在唯一合法动作时必须停止并说明原因。
- `BR-037` 自动检查、测试、构建、审计或受控命令失败，以及信息不足或状态无法解析时，必须失败关闭并保留证据，不得自动降级、跳过或宣称完成。
- `BR-038` 工作项默认串行执行；只有无直接或间接依赖、声明文件范围不重叠、共享接口和共享状态无语义冲突且隔离风险可接受时，才能进入同一并行组。
- `BR-039` 并行判定必须同时检查依赖、文件范围、共享接口/状态和运行资源；任一项不确定即退化为串行。
- `BR-040` 并行执行中出现未声明范围漂移、文件冲突、共享状态冲突或前置条件失效时，受影响工作必须停止并转人工处理。
- `BR-041` 启动下一版本周期必须保留上一版本的完成状态、Gate、运行、审计和交付证据，不得覆盖为新周期状态。
- `BR-042` 复盘只记录可追溯事实；token、调用量或货币成本不可获得时记录为“未知”及原因，不得估算成事实。
- `BR-043` 复盘建议不得自动修改需求、方案、工作项、测试、规则或历史证据；采纳建议必须进入新的受控变更或版本周期。
- `BR-044` 编排和复盘记录不得包含密钥、完整环境变量、不必要的生产数据或第三方模型输入正文。
- `BR-045` v3.0 不接入真实多模型审计、真实 CI、模板化初始化、真实 Git 工作树或公网部署。

### FR-034 启动并记录下一版本周期

- 状态：APPROVED
- 业务目的：让已完成项目无需人工改写历史状态即可开始下一版本。
- 前置条件：当前项目处于已完成状态，不存在活动运行、项目锁或未关闭审计修复循环。
- 输入：新版本号、版本主题、负责人和启动理由。
- 行为：验证版本号递增和前置条件，创建新周期记录，将当前周期置于业务发现阶段，并引用上一周期完成快照。
- 输出：新的活动周期、历史周期引用和不可覆盖的启动记录。
- 异常：版本号无效、存在活动运行或历史快照无法建立时拒绝启动，原完成状态保持有效。
- 验收标准：AC-072、AC-073
- Phase 3：YES

### FR-035 判断唯一合法下一动作

- 状态：APPROVED
- 业务目的：减少人工识别流程状态和下一步命令造成的遗漏与误操作。
- 前置条件：项目存在可解析的活动周期、阶段契约和必需产物。
- 输入：当前状态、阶段门、有效产物、活动运行、验证及审计结果。
- 行为：按契约计算可执行、等待人工、阻塞或完成状态；只有恰好一个合法动作时才允许执行建议。
- 输出：下一动作、判定状态、依据和受控入口，或明确的等待/阻塞原因。
- 异常：状态矛盾、产物缺失、多个动作冲突或工具异常时失败关闭。
- 验收标准：AC-074、AC-075、AC-076
- Phase 3：YES

### FR-036 自动推进非人工阶段

- 状态：APPROVED
- 业务目的：自动完成结果可由契约和验证确定的重复推进操作，同时保留人工决策权。
- 前置条件：FR-035 返回唯一合法动作，且该动作不属于 BR-035 的人工 Gate。
- 输入：合法动作、前置检查、受控命令及其结果。
- 行为：执行一次受控动作，记录输入摘要、开始/结束时间、退出结果和新状态；成功后重新判断下一动作。
- 输出：成功推进记录，或停止状态及失败证据。
- 异常：遇到人工 Gate、失败、超时、状态未按预期改变或重复执行请求时停止；不得重复产生副作用。
- 验收标准：AC-077、AC-078、AC-079
- Phase 3：YES

### FR-037 生成串行顺序或安全并行组

- 状态：APPROVED
- 业务目的：在保持正确性的前提下减少彼此独立工作项的等待时间。
- 前置条件：存在两个或以上 READY 工作项，且每项均声明依赖、文件范围及共享接口/状态范围。
- 输入：工作项、依赖关系、影响范围、运行资源和当前活动工作。
- 行为：先构建依赖顺序，再按 BR-038、BR-039 形成稳定的串行顺序或安全并行组；默认结果为串行。
- 输出：带判定理由的调度计划，以及未进入并行组的冲突说明。
- 异常：循环依赖、范围缺失、语义冲突或隔离无法证明时拒绝并行；无法形成合法顺序时整体阻塞。
- 验收标准：AC-080、AC-081、AC-082
- Phase 3：YES

### FR-038 监测并行范围漂移与冲突

- 状态：APPROVED
- 业务目的：避免调度前安全、执行中越界的并行工作破坏项目状态。
- 前置条件：至少一个并行组正在执行。
- 输入：批准范围、实际修改范围、共享状态变化、运行状态和依赖状态。
- 行为：在执行边界和合并前比较批准范围与实际变化；发现漂移或冲突时停止受影响工作并记录人工接管信息。
- 输出：继续许可，或包含工作项、冲突对象、最后安全状态和恢复建议的停止记录。
- 异常：无法读取实际变化或冲突判断不确定时按冲突处理，不继续并行。
- 验收标准：AC-083、AC-084
- Phase 3：YES

### FR-039 采集基础成本、延迟和质量指标

- 状态：APPROVED
- 业务目的：为交付复盘提供可比较、可追溯的事实数据。
- 前置条件：阶段动作、工作项运行、验证或审计产生记录。
- 输入：ISO 8601 开始/结束时间、运行结果、失败/重试、测试与审计摘要，以及提供方返回的使用量和成本元数据。
- 行为：记录耗时毫秒、成功/失败/重试次数、测试通过/失败数、审计结论、输入/输出/总 token、调用量、货币金额、币种和数据来源；不可得字段记录未知及原因。
- 输出：关联周期、阶段、工作项或运行编号的指标记录。
- 异常：结束早于开始、计数为负、来源缺失或字段矛盾时拒绝该指标并记录数据质量问题，不影响原业务证据。
- 验收标准：AC-085、AC-086、AC-087
- Phase 3：YES

### FR-040 生成交付复盘并管理改进建议

- 状态：APPROVED
- 业务目的：在交付完成后识别流程偏差、质量问题和下一周期改进机会。
- 前置条件：Gate 3 已批准，当前周期具有运行、验证、审计和交付记录。
- 输入：周期事实、计划与实际状态、FR-039 指标、失败/恢复历史和交付结果。
- 行为：汇总范围、耗时、失败与重试、质量和可得成本，区分事实、推断、数据缺口和建议，并链接来源。
- 输出：不可覆盖的复盘报告，以及等待负责人接受、拒绝或延期的建议清单。
- 异常：数据缺失时仍可生成标明缺口的复盘，但不得补造数值；Gate 3 未批准时不得生成最终交付复盘。
- 验收标准：AC-088、AC-089、AC-090
- Phase 3：YES

### Phase 3 非功能需求

- `NFR-016` 确定性：相同有效输入必须生成相同的下一动作和调度分组；排序规则必须稳定。
- `NFR-017` 幂等性：同一动作标识被重复请求时不得重复推进阶段、重复启动工作或覆盖历史记录。
- `NFR-018` 历史完整性：周期启动、自动推进、并行冲突、指标和复盘均追加记录，不静默覆盖既有事实。
- `NFR-019` 安全性：编排与复盘遵守 BR-044，错误输出也不得泄露秘密。
- `NFR-020` 可恢复性：每次自动动作和冲突停止都能定位最后一致状态、失败原因和合法恢复入口。
- `NFR-021` 可复用性：Phase 3 契约不依赖 Todo 业务字段，能够应用于遵循 Phase 2 契约的其他项目。
- `NFR-022` 保守并行：无真实 Git 工作树隔离时，任何无法证明安全的并行候选都必须退化为串行。

## Requirements Baseline v2.0：工程质量闭环

### GOAL-004 建立可追踪且独立验收的工程质量闭环

- 状态：APPROVED
- 目标：在实施规划前建立风险分级的技术方案，在执行完成后建立独立验收，使需求、方案、工作项、测试和证据形成可检查闭环。
- 成功标准：缺少必需追踪、存在未处理高风险、独立验收失败或沿用已失效证据时，流程必须拒绝继续交付；修复后可基于完整历史重新验证。

### Phase 2 业务规则

- `BR-025` 所有需求变更都必须经过 `solution-design` 影响评估，不得静默跳过。
- `BR-026` 低风险变更可以使用简化方案，但必须记录风险等级和简化理由；中高风险变更必须形成完整技术方案。
- `BR-027` 涉及数据模型、安全、权限、外部系统、不可逆操作、公共 API 或跨模块修改时，必须按完整技术方案处理。
- `BR-028` 未关闭或未被负责人明确接受的高风险项必须阻止实施规划通过。
- `BR-029` 需求、方案、工作项、测试与证据必须建立双向追踪，任何必需链接缺失都不能宣称完整覆盖。
- `BR-030` 已批准需求发生变化时，必须列出受影响方案、工作项、测试和证据，并使不再有效的下游状态失效。
- `BR-031` `acceptance-audit` 不得修改被审计的生产实现或实现测试；审计失败必须退回 `execute` 修复，再独立复验。
- `BR-032` 审计失败、执行修复和复验结果必须分别保留，不得以成功结果覆盖历史失败。
- `BR-033` 独立验收样例不得直接复用被审计实现的内部测试夹具作为唯一判定依据。
- `BR-034` Phase 3 编排、交付复盘、多模型、并行工作树、CI、项目模板化和量化成本指标不属于 v2.0 范围。

### FR-026 评估方案风险并选择设计深度

- 状态：APPROVED
- 业务目的：让所有需求变更都经过一致的方案影响判断，同时避免低风险修改承担不必要的完整设计成本。
- 前置条件：Gate 2 已批准需求基线，或存在已批准的 `CHG-*` 变更。
- 输入：需求、验收标准、现有架构约束和变更影响信息。
- 行为：评估变更影响和风险等级；低风险生成带理由的简化方案，中高风险或命中 BR-027 的变更生成完整方案。
- 输出：风险等级、设计深度、判断理由、受影响边界和方案状态。
- 异常：信息不足以判断风险时不得默认低风险，必须标记为待确认并阻止进入规划。
- 验收标准：AC-054、AC-055、AC-056
- Phase 2：YES

- 输出：可供实施规划引用的方案与风险登记。
- 异常：存在未处理且未被负责人接受的高风险时，方案不得通过确认门。

### FR-028 建立并检查双向追踪矩阵

### FR-030 执行自动契约检查

- 状态：APPROVED
- 业务目的：自动发现文档、状态、引用、阶段门和证据之间的不一致。

### FR-031 执行独立验收审计

- 状态：APPROVED
- 业务目的：在交付前用独立视角验证批准需求、契约和证据，而不是只相信执行流程的自证结果。
- 前置条件：计划工作项均已完成自身验证，且不存在活动运行或未恢复项目锁。
- 输入：需求基线、技术方案、追踪矩阵、实施结果、独立验收样例和执行证据。

- 异常：证据缺失、独立样例失败或审计工具异常时均不得批准交付。
- 验收标准：AC-065、AC-066、AC-067

### FR-032 退回修复并独立复验

- 状态：APPROVED
- 业务目的：让审计失败形成可恢复闭环，同时保留完整失败与修复历史。

- 验收标准：AC-028、AC-029、AC-030、AC-031
- 首版：YES

- 异常：无。
- 验收标准：AC-032

## 业务目标

### GOAL-001 快速创建个人任务

- 状态：APPROVED
- 目标：个人用户可在手机端通过单条自然语言快速创建结构化任务，减少手工录入。
- 成功标准：用户提交包含任务描述及可识别属性的单条自然语言后，系统自动提取属性并直接创建任务。

### GOAL-002 完成基本任务管理

- 状态：APPROVED
- 目标：个人用户可在本机查看和维护自己的任务。
- 成功标准：用户可查看、编辑、完成、删除及按标签筛选任务。

## 业务规则

### BR-001 首版用户边界

- 状态：APPROVED
- 规则：首版仅支持个人使用，不提供账户、登录、跨设备同步或家庭/小组共享。

### BR-002 任务结构

- 状态：APPROVED
- 规则：AI 可提取的任务属性为任务名、时间、标签和优先级；任务名为创建任务所需的最小内容。

### BR-003 AI 直接创建

- 状态：APPROVED
- 规则：AI 返回确定的解析结果后，系统直接创建任务，不要求用户预先确认。

### BR-004 无法确定属性时的降级

- 状态：APPROVED
- 规则：AI 无法确定解析结果时，不拆解输入，以整段原文作为任务名创建任务，并提示“未识别属性”。

### BR-005 API 失败时的降级

- 状态：APPROVED
- 规则：第三方大模型 API 超时、不可用或返回错误时，以整段原文作为任务名创建任务，并提示“AI 解析失败”。

### BR-006 删除不可恢复

- 状态：APPROVED
- 规则：删除任务前必须二次确认；确认删除后任务不可恢复。

### BR-007 首版数据边界

- 状态：APPROVED
- 规则：首版不处理敏感数据；首次使用 AI 创建任务前，必须提示输入会发送给第三方大模型且不得包含敏感数据，并在用户确认后才能继续。

## 功能需求

### FR-001 使用自然语言创建任务

- 状态：APPROVED
- 业务目的：减少用户逐字段录入任务的操作。
- 前置条件：用户位于任务创建入口，第三方大模型 API 可用。
- 输入：一条非空自然语言文本。
- 行为：系统将文本发送给第三方大模型解析任务名、时间、标签和优先级，并依据解析结果直接创建一条任务。
- 输出：已保存的结构化任务和创建成功结果。
- 异常：解析不确定时执行 FR-002；API 失败时执行 FR-003；空输入规则见 ASM-001。
- 验收标准：AC-001、AC-002、AC-015
- 首版：YES

### FR-002 处理无法确定的解析结果

- 状态：APPROVED
- 业务目的：解析不确定时仍保留用户输入，避免任务丢失。
- 前置条件：用户提交了非空文本，AI 返回无法确定的解析结果。
- 输入：用户提交的完整原文。
- 行为：系统不拆解原文，将完整原文作为任务名创建任务。
- 输出：已创建的任务及“未识别属性”提示。
- 异常：无。
- 验收标准：AC-003
- 首版：YES

### FR-003 处理第三方 API 失败

- 状态：APPROVED
- 业务目的：外部服务故障时仍允许用户记录任务。
- 前置条件：用户提交了非空文本。
- 输入：用户提交的完整原文，以及 API 超时、不可用或错误结果。
- 行为：系统将完整原文作为任务名创建任务。
- 输出：已创建的任务及“AI 解析失败”提示。
- 异常：API 失败本身由本需求处理。
- 验收标准：AC-004
- 首版：YES

### FR-004 查看任务

- 状态：APPROVED
- 业务目的：让用户查看已创建任务及其当前信息。
- 前置条件：无。
- 输入：用户打开任务列表。
- 行为：系统读取本机保存的任务。
- 输出：任务列表；每条任务呈现任务名及已有的时间、标签、优先级和完成状态。
- 异常：没有任务时显示空状态。
- 验收标准：AC-005、AC-006
- 首版：YES

### FR-005 编辑任务

- 状态：APPROVED
- 业务目的：允许用户纠正 AI 解析结果或更新任务。
- 前置条件：目标任务存在。
- 输入：用户对任务属性的修改。
- 行为：系统允许用户编辑任务名、时间、标签和优先级，并保存用户确认的修改。
- 输出：更新后的任务。
- 异常：保存失败时不得覆盖原任务，并提示失败。
- 验收标准：AC-007
- 首版：YES

### FR-006 完成任务

- 状态：APPROVED
- 业务目的：记录任务已经完成。
- 前置条件：目标任务存在且未完成。
- 输入：用户执行完成操作。
- 行为：系统将未完成任务标记为已完成，并允许用户将已完成任务恢复为未完成。
- 输出：任务显示并保存用户选择的完成状态。
- 异常：目标任务不存在时不得产生状态变更。
- 验收标准：AC-008
- 首版：YES

### FR-007 删除任务

- 状态：APPROVED
- 业务目的：允许用户清理不再需要的任务，同时防止误删。
- 前置条件：目标任务存在。
- 输入：用户发起删除并对二次确认作出选择。
- 行为：取消确认时保留任务；确认时永久删除任务。
- 输出：取消后任务仍存在；确认后任务不再出现且不可恢复。
- 异常：目标任务不存在时不得影响其他任务。
- 验收标准：AC-009、AC-010
- 首版：YES

### FR-008 按标签筛选任务

- 状态：APPROVED
- 业务目的：帮助用户聚焦指定标签下的任务。
- 前置条件：任务中存在标签。
- 输入：用户选择一个标签。
- 行为：系统仅展示包含所选标签的任务。
- 输出：符合标签条件的任务列表；没有匹配项时显示空结果。
- 异常：无。
- 验收标准：AC-011、AC-012
- 首版：YES

### FR-009 本机持久保存任务

- 状态：APPROVED
- 业务目的：保证用户退出并重新打开应用后仍可继续管理任务。
- 前置条件：系统成功创建或修改了任务。
- 输入：任务及其状态变更。
- 行为：系统将任务数据保存在本机，不上传至账户或同步服务。
- 输出：重新打开应用后可读取未被删除的任务及最新状态。
- 异常：本机保存失败时提示失败，不得虚假显示保存成功。
- 验收标准：AC-013
- 首版：YES

### FR-010 展示第三方 AI 数据提示

- 状态：APPROVED
- 业务目的：让用户知道自然语言任务将发送给第三方服务，并避免输入敏感数据。
- 前置条件：用户准备首次使用 AI 创建任务。
- 输入：用户对数据提示作出的确认或拒绝。
- 行为：系统提示“输入会发送给第三方大模型，请勿输入敏感数据”；仅在用户确认后进入 AI 创建流程，拒绝时不发送输入且不创建任务。
- 输出：确认后可继续 AI 创建；拒绝后结束本次创建流程。
- 异常：用户未作出选择时不得发送输入。
- 验收标准：AC-014
- 首版：YES
